# Security posture

This document describes the intended boundary in [Railway IaC](../.railway/railway.ts) and [local Compose](../docker-compose.yml). It does **not** assert that these changes have been applied or that deployed services are private. Existing public routes require a provider inventory, reviewed removal targets and separately approved changes.

A separate coordinator read-only inventory on **2026-11-19** confirmed that Visualizer production has public HTTP only on frontend/gateway, no HTTP domains on private services, and no TCP proxy on the indexer. That dated networking observation is independent of this local source work. It is not evidence that new image changes are deployed or that ingestion documentation routes have been tested in the new image. Recheck after any approved deployment or routing change.

Only `frontend` and `snapshot-gateway` may receive generated Railway HTTP domains. Production custom domains are exactly `protocol-visualizer.olympusdao.finance` and `protocol-visualizer-api.olympusdao.finance`; preview custom-domain maps are empty, with generated domains for these same two public services provisioned separately. No public TCP proxy is intended for any service.

The frontend does not call ingestion/Hasura directly. The boundary is browser → gateway → private bucket, with indexer → PostgreSQL/Hasura → publisher → bucket on the ingestion side. Internal HTTP and credential possession remain trust assumptions; network privacy is not per-service authorization.

## What the source and tests establish

- IaC applies native networking maps **after** SDK normalization and group expansion. Private resources emit explicit empty generated/custom HTTP-domain maps. TCP maps contain `null` tombstones for canonical managed ports and every port imported from the current environment configuration; PostgreSQL includes port 5432. Empty TCP maps are sparse no-ops, not removal instructions.
- The plan-time lookup reads `serviceInstances`, domains, volumes and `config(decryptVariables: false)`. Config stays in memory; variables are never logged or saved. Incomplete/paginated results, duplicate or unknown services, unaccounted active config IDs, malformed ports or existing private HTTP domains stop evaluation. Empty existing inventories remain valid for new previews.
- Regression tests evaluate and serialize the real SDK/project output in production and preview contexts, including grouped private resources, discovered unexpected ports and malformed inventories. These are SDK/project and mocked-provider tests, not a full native CLI or backend apply test.
- CLI 5.75's [native networking diff](https://github.com/railwayapp/cli/blob/v5.75.0/src/iac/change_set.rs) treats TCP entries as sparse patches: named `null` values request removal. Its normal plan/apply path uses the evaluated graph; the separate environment compiler's default database proxy is not proof of normal apply behavior. Independent characterization of the exact upstream TCP helper is narrower than a full CLI/backend test.
- The same native diff removes `serviceDomains` and `customDomains` from the networking change path. Empty domain maps do **not** prove that existing HTTP routes will be removed. The provider-domain preflight blocks such exposure; it does not remove it.
- The real-image integration must request `/docs`, `/openapi.json` and `/llms.txt` through the running indexer wrapper and assert 404, plus `/healthz` 200 and a working readiness response. A prepared test or static route inventory is not a passing image result. The source wrapper proxies unknown paths to Envio, so gateway route tests cannot substitute for this check.

## Operator acceptance before deployment

1. Inventory generated/custom HTTP domains and active TCP proxies for the exact project/environment, including services outside the expected list. Read provider metadata without exposing variable values. Record the current revision and immutable image identities.
2. Review any undesired existing HTTP domains and obtain separate approval for their provider removal. The CLI's empty-map behavior cannot establish removal. Re-read the actual domain inventory afterward; source preflight must fail until private services have no domains.
3. Follow the [native plan/apply runbook](railway-self-hosting.md#manual-iac-plan-and-deployment) for explicit project/environment selection, private plan permissions, approval and JSON-result verification. Keep the reviewed artifact unchanged. Existing CI retains target/tree/revision checks and blocks the prepared main database image transition from automatic apply.
4. After approved changes, re-inventory all HTTP domains/TCP proxies and verify actual reachability, private communications, database paths/TLS, persistence, health/readiness and ingestion docs absence. Source checks, scans, empty maps and native exit zero do not establish deployed privacy.

## Local bindings

Every published Compose port binds `127.0.0.1`, including the frontend and gateway. Defaults are frontend 3000, gateway 8082, Hasura 8080, indexer 9898, PostgreSQL 5432, eRPC 4000 and MinIO API/console 9000/9001. `rpc-cache-postgres`, bucket initialization and scheduled jobs publish no host port. Containers still communicate on the Compose network. Loopback limits LAN exposure; it does not authenticate another local process. Development default passwords and the local Hasura console are not production credentials or policies. See [local stack](local-stack.md).

See the [PG18.6 reset/reindex runbook](postgresql18-rebuild.md) for the data inventory and separate destructive approval boundary. Source review does not prove that every live row is rebuildable. Preserve external metadata/effect caches, Hasura customizations and backups before approving the main reset; keep the bucket and separate eRPC storage intact. Envio 3.14.1 and its fail-closed startup/reset adapters remain unchanged.

The saved native CLI compiler branch emits explicit production PGDATA `/var/lib/postgresql/data/pgdata` under its child mount. Image ENV alone does not prove the live effective path or a cache persistence problem. SDK/source, compiler and actual deployment evidence are distinct; verify effective live bindings during an authorized release preflight. No production path relocation or live reset is performed here. Historical PG16/17 scan receipts remain historical; this pin/preparation is not a vulnerability-remediation or fresh clean-scan claim. Review applicable index/extension and backup-chain release notes before separately approved operations.

## Validation, tools and residual gaps

Use the [validation contract](validation.md) for pinned tools, source/image/integration commands, native scan policies and evidence. Envio remains a compatibility exception: Visualizer 3.14.1 and Metrics 3.14.0 retain their existing native adapters; Indexer 3.15.0 is separate. Upgrading those adapters requires its own review.

Residual findings to carry into the cross-repository review:

- Gateway `createS3Reader` still fully buffers S3 bodies with the SDK's `Body.transformToString`; it only returns `ContentLength` metadata afterward. There is no streaming byte cap in that adapter. Readiness has abort/deadline logic, while ordinary public object reads do not acquire the same per-object deadline. This differs from the Metrics reader's bounded streaming policy; no artifact-reader refactor is included here.
- Bucket reader/write credential separation is not established by source-level method selection. Any provider IAM change requires a separately reviewed credential/permission operation.
- Provider image findings remain advisory; local fixture exclusions and actual coverage are recorded in [native validation output](validation.md). No global gosu/CVE waiver is added. Historical scanner counts do not prove exploitability or a fresh clean scan.
- Source audit, durable receipts, shared tool versions and loopback bindings were earlier inconsistencies and are now implemented locally. Their final acceptance depends on the current canonical receipts, not earlier runs on older pins.
